# 采购与物料需求功能总结

## 材料范围

本总结依据本目录 `1.png`～`8.png`、新增的 `9-采购底稿明细.png`、`10-采购底稿列表.png`、`11-采购底稿字段说明.png`、`readme.txt` 及用户业务澄清。其中 `1.png`～`5.png` 是物料需求计算向导，`6.png`～`8.png` 是采购单录入与取单。文字说明中的业务要求单独标明，不将其等同于已经验证的系统行为。

## 一句话概括

采购有三种入口：物料需求计算形成采购建议或底稿、仓库提出请购、采购直接录入商品。采购人员核对后形成采购订单；采购人和供应商是文字材料明确要求的必填项。

## 业务澄清：采购底稿与请购单分开管理

本节依据用户补充说明及新增三张截图，为后续 demo 实现的最新口径，优先于此前将需求分析结果当作请购单的实现。

### 两条采购来源

```text
计划性采购：生产计划 + BOM + 可用库存 → 需求分析 → 系统生成采购底稿 → 采购核对 → 采购单 → 收货入库
临时性请购：车间装机临时发现缺料 → 纸质请购交仓库 → 仓库在系统录入请购单 → 采购单 → 收货入库
```

- 请购单由仓库根据线下临时需求录入，不再承接系统 BOM 展算结果。纸质流转作为业务背景，本次不增加拍照、上传或电子审批。
- 采购底稿由系统按 BOM 和库存自动生成，是可追溯的采购准备记录；与手工请购分开保存、查询和统计。
- 两者均可转采购单；采购单必须分别保留来源底稿或来源请购，不能混用来源编号。

### 单头与列表字段

底稿单号、日期、性质（示例为“需求”）、采购人及姓名、审核人及姓名、部门及名称、送货地址、备注、制单人、结束标识、税前金额合计、价税金额合计、机种名称。列表还显示审核时间、审核码、项目及项目名称、送货邮编等。

### 物料行字段

序号、结束码、供应商及简称、机种名称、品号、品名、交易数量、BOM 用量、品牌、规格、预交货日期、前置单据、币种、交易单位、含税标识、含税单价、单价、换算分子等。右侧有截断内容，不补猜不可见字段。

**数量必须分列：** BOM 需求量反映计划总用量，需购买数量反映扣除库存后的缺口，不能把两者显示为同一个数。例如 demo 计划需要 5 个 PLC，可分配库存为 2 个，应保留 BOM 需求 5、需购 3。

### 本次 demo 调整

1. 需求分析提供底稿预览，显示 BOM 需求量、库存、其他计划占用、待转底稿/在途覆盖、需购数量及来源计划。
2. 点击“生成采购底稿”后保存本次计算快照，进入独立“采购底稿”记录列表；后续库存变化不回写已保存的计算结果。
3. 底稿详情保留完整 BOM 展算行，包括无需新增采购的行；转采购只带入需购数量大于 0 的行。
4. 底稿整单转采购，采购人及供应商必填，防重复转单；未转底稿与在途采购均覆盖对应计划需求，避免重复生成。
5. 旧 demo 自动生成且关联计划的请购单迁移为底稿，保留原计划、数量和已生成采购关系；手工请购、库存、收货及用户档案不重置。旧数据没有计算时的库存快照，迁移详情明确标为缺失，不按当前库存伪造历史值。
6. 手工请购保持独立入口。需求分析不再向请购记录写数据，手工请购不自动占用某个生产计划。
7. 审核、结束、拆分、分供应商采购、税价换算等规则未明确，暂不实现；未知单头资料留空。原系统的“已审核/指定结束”等只作为截图事实，不伪装为 demo 已实现流程。

为保持演示范围，前置单据暂直接关联现有生产计划；没有额外虚构一层独立需求计划实体。

## 材料明确描述的业务流程

`readme.txt` 描述了两条主要路径：

```text
工程文员上传 BOM
  → 物料需求计算（需核对仓库库存）
  → 采购底稿
  → 采购核对
  → 采购订单

仓库填写请购单
  → 采购新增采购订单
  → 从请购单或采购底稿取单
  → 采购订单
```

补充边界：文字说明写的是“选择对应的 BOM 表”，但需求计算截图中的计划来源是“订单”或“生产计划”。BOM 如何上传、如何与订单或计划关联，当前材料未展示，不能将二者直接等同。

## 物料需求计算

### 向导步骤

检查设置 → 选择计划来源 → 选择来源单据 → 订单需求确定 → 需求建议生成 → 需求发放 → 发放记录查询。

截图展示到需求建议及发放按钮，未展示发放后的结果和记录查询页面。

### 编号检查

界面提示需求发放会自动生成单据，因此编号方式不能为手动编号。检查对象包含工单、委外单、采购底稿和采购单。

### 计划来源与需求量来源

- 计划来源支持订单或生产计划。
- 订单可按订单号、订单日期、预交货日期、品号筛选。
- 生产计划可按计划单号、开单日期、预计开工日、预计完工日、主件品号筛选。
- 订单需求量来源可选“未交量（需求量－已交量）”或“订单生产采购联动”。
- 联动选项显示公式：需求量－工单量－MRP量－采购底稿量－委外量－生产计划量。各数量的统计状态及去重方式未展示。

### 库存展算选项

页面展示四种公式，以下按界面文字记录，不额外推导其后台算法：

1. 需求量。
2. 需求量－实际在库量。
3. 需求量－（实际在库量－安全存量）。
4. 需求量－（实际在库量－安全存量＋预计入库量－预计出库量）。

截图当次勾选的是“需求量”，因此不能认定截图中的本次计算已经扣除库存。文字流程要求计算时确认库存，重建时应明确默认公式和参与计算的仓库范围。

### 其他计算选项

- 生产计划按“同品号、预计完工日”合并发放。
- 采购计划按“同品号、预交货日”合并发放。
- 开工、完工日早于系统日期时是否改成系统日期。
- 可用量不足时是否考虑补货。
- 是否考虑替代件。
- 是否带出主供应商。

这些是截图可见选项，不能据此认定所有组合已执行验证。

### 建议与发放

结果页可见“厂内源工单”“委外源工单”“工单”“委外”“采购”页签，当前展示采购页签。采购建议包含品号、品名、规格、库存单位、采购单位、预交货日等字段，可勾选发放。

页面还提供“采购底稿直接抛转采购单”及采购日期选项。因此，界面存在直接转采购单的路径，但文字流程要求先由采购核对；两者如何兼容应在重建时明确，不能默认跳过核对。

## 采购订单

### 建单方式

1. **取单建单**：从请购单、询价单或采购底稿选择来源明细，可按单号、日期和采购状况等条件查询。
2. **直接建单**：在采购明细中直接录入或选择品号，不依赖上游单据；`7.png` 的标注明确说明这一点。

### 单据字段

| 区域 | 可见字段 |
| --- | --- |
| 单据头 | 单号、日期、公司、供应商、采购人、部门、采购人电话、币种、汇率、审核人、项目、性质、送货地址。 |
| 变更与追踪 | 变更版本、变更日期、变更原因、打印次数、打印人员、打印时间、项目号。 |
| 金额关联 | 订金已开票金额（含税）、订金已付金额。 |
| 商品明细 | 序号、品号、品名、规格、单位、含税标识、数量、含税单价、税前金额、单价等。 |
| 取单明细 | 交易单位、交易数量、换算分子、换算分母、库存单位、库存单位数量、需求日期等。 |

必填规则依据 `readme.txt`：采购人、供应商必填。其他字段是否必填、何时校验，不能仅凭界面颜色或下划线判断。

工具栏可见审核、结束、交货、历史、发票、账款等入口，但本组截图未展示对应内容，不能认定具体流转和财务处理规则。

## 跨模块依赖

- **商品与 BOM**：提供品号、组成关系、采购来源、主供应商和采购单位等基础资料。
- **库存**：提供实际在库量、安全存量及预计收发数据；哪些仓库参与计算需要与库存配置统一。
- **生产**：订单和生产计划可触发需求，结果存在工单和委外等不同建议类型。
- **采购**：建议或底稿经核对后形成采购订单，同时保留来源关系。

## Web ERP 功能划分建议

| 建议入口 | 包含内容 |
| --- | --- |
| 计划与生产 → 物料需求 | 来源选择、库存口径、展算、建议核对、发放和历史记录，整合为同一个流程。 |
| 采购管理 → 请购 | 仓库或业务人员提出需求，查看采购进度。 |
| 采购管理 → 采购建议 | 集中核对物料计算产生的底稿，确认供应商、数量、日期后转单。 |
| 采购管理 → 采购订单 | 统一承接请购、询价、底稿及手工录入，关联变更和执行进度。 |
| 配置中心 → 业务规则 | 单据编号、需求计算、合并、日期处理等规则集中维护，保留业务含义和校验。 |

不建议把每个计算参数建成独立菜单，也不建议把需求展算规则当成任意字段随意配置。

## 待确认事项

- BOM 上传格式、校验规则、版本，以及与订单或生产计划的关联方式。
- 实际在库量是否过滤不参与可用量的仓库，需求公式中的库存与库存模块可用量如何对应。
- 已下工单、已建底稿、已下采购单和已发放需求如何避免重复计算；取消或变更后如何释放数量。
- 发放是否默认先生成底稿，直接转采购单是否需要采购核对或授权。
- 一份需求是否允许拆单、部分转单、多供应商采购，剩余量如何跟踪。
- 多单位换算、税价金额精度、币种汇率及供应商价格取值规则。
- 审核、收货、退货、发票和付款的状态衔接；本目录未提供这些环节的操作截图。
