# WSN ERP 纯前端演示

基于已有模板的 Vue 3、TypeScript、Element Plus 和 Vite，提供库存、采购、生产三个模块。无需登录、后端、数据库或接口服务，浏览器直接加载 mock 数据。

## 启动

需要 Node.js ≥ 20.19，使用模板锁定的 **pnpm 9.15.3**。保留原有依赖锁文件，没有新增依赖。

```bash
cd D:/projects/WSN/web
pnpm install --frozen-lockfile
pnpm dev
```

打开 http://127.0.0.1:5173/ 。如本机 pnpm 版本不同，可用 `pnpm dlx pnpm@9.15.3 install --frozen-lockfile` 安装、`pnpm dlx pnpm@9.15.3 dev` 启动。

```bash
pnpm type-check
pnpm test:demo
pnpm build
pnpm preview
```

构建输出为 `dist/`，可部署至普通静态文件服务器，预览地址为 http://127.0.0.1:4173/ 。不支持通过 `file://` 双击 HTML 运行。

## 部署到 GitHub Pages

仓库根目录的 `.github/workflows/pages.yml` 会在推送到 `master` 或 `main` 时自动安装锁定依赖、运行演示测试、检查类型并构建，将 `web/dist/` 发布至 GitHub Pages；也支持在 Actions 页面手动运行。

1. 将整个仓库上传到 GitHub，保留根目录 `.github/` 和 `web/` 的位置。
2. 打开仓库 **Settings → Pages → Build and deployment**，将 **Source** 设为 **GitHub Actions**。
3. 推送代码，或在 **Actions → 部署 GitHub Pages → Run workflow** 手动触发。
4. 等待部署成功，通过部署记录中的网址访问，通常为 `https://<用户名>.github.io/<仓库名>/`。

当前配置使用相对资源路径和 hash 导航，支持仓库子路径。无需提交 `dist/`，也无需配置后端环境变量。数据仅保存在访问者自己的浏览器中，不会跨用户或设备共享。

免费账户可使用公开仓库部署；私有仓库使用 Pages 需要支持的 GitHub 付费方案。仓库内 `web/.github/workflows/ci.yml` 是保留的模板配置，GitHub 不会从该嵌套目录加载工作流。

## 已实现页面

| 模块 | 页面及功能                                                                               |
| ---- | ---------------------------------------------------------------------------------------- |
| 库存 | 库存记录、仓库与物料档案、出入库流水、领料单、成品库存                                   |
| 采购 | 按计划分组、物料逐行取料的采购底稿、请购单、跨计划采购、金额录入、审核与反审核、同供应商合并、分批收货 |

## 推荐演示流程

1. 在工单管理创建工单，点击“安排计划”选择手工创建或 Excel 导入，自动带入当前工单；也可在生产计划新增时选择工单。一个工单可关联多个计划。
2. 选择预设产品创建计划，或导入 BOM Excel 并选择关联工单。导入只匹配已有物料，不覆盖属性；不存在的物料按 BOM 字段新建，计划详情展示“本次新建”并可进入档案。
3. 在生产计划点击“分析缺料”打开需求分析弹窗；库存足够时不产生底稿，不足时只对差额生成底稿。一个生产计划只生成一张底稿，内部保存多条缺料物料及计算快照。
4. 在底稿列表多选底稿，打开转采购弹窗查看所有所选底稿的物料，再勾选具体待采购物料；可跨计划按供应商组合采购，已转物料禁选，未选物料继续待采购。
5. 未审核采购单可继续从底稿、请购单取料，或手动选物料添加。金额在每条采购物料旁填写，表示该行总额，可保持空；合计由明细金额汇总，打印展示各行金额。
6. 审核后到“收发货 → 收货单”页面新建收货单，填写本次数量。确认立即生成不可修改的收货单、入库单和库存流水。允许分次收货，全部物料收齐后采购单完成。
7. 在领料单页面选择计划，核对全部需求和各仓分配后确认，生成领料单及出库记录并扣减库存。生产计划的“生产领料”也进入该页面。
8. 在生产计划执行完工入库，成品仓增加对应成品数量。工单前四种状态在工单详情中人工切换。
9. 将工单切换为待出货，在“收发货 → 成品发货”页面创建发货单并填写物流公司和物流单号。全部关联计划完工、成品库存足够后可发货，生成出库记录、扣减成品库存并将工单改为已发货。
10. 刷新后数据保留；右上角“重置数据”恢复初始演示数据。

## 演示规则和边界

- 全部业务仅在当前浏览器本地执行，无后端、账号流转或真实物流轨迹服务。
- 采购单不直接关联生产计划；采购明细通过来源底稿追溯计划。手工物料和临时请购不强制关联计划。
- 采购审核状态为未审核、已审核，收货进度独立为未收货、部分收货、全部收货。只有已审核单可以收货，发生任何收货后禁止反审核。
- 同供应商的未审核采购单可合并；结果仍未审核，来源明细保持完整。明细金额全部已填时求和，存在未填时合计保持空，后续逐行填写。原单保留合并去向，不重复执行业务。
- 只有正常且参与可用量计算的仓库参与缺料分析及生产领料。已有底稿的计划按生成顺序分配原有库存，采购到货保留来源计划归属，避免跨计划重复缺料或抢占到货。
- 领料当前按整份计划一次办理，允许调整仓库分配，总数量须等于 BOM 需求。库存不足不允许负库存或部分成功。
- 完工当前按整份计划一次办理，进入 CP01 成品仓；发货按工单全部关联计划的成品一次办理，不支持部分发货。
- 工单立项中、采购中、装配中、待出货由人工切换；已发货仅由发货操作触发。
- 保存先在数据副本中校验和修改，再一次性持久化；失败明确提示，不发布部分更新。不支持跨标签页并发编辑。
- 旧浏览器数据在读取时迁移：同一计划的物料底稿合并为一张底稿，采购明细同时保留底稿号和来源物料行，旧采购收货状态保留，未关联工单的旧计划补建工单。缺失历史快照明确留空，不伪造收货单据。
- 数量为 1～100000 的正整数；BOM 缺失数量及单位沿用现有导入缺省约定，预览可修改。参考单价不等于成交价格，不用于替代采购手填金额。
- 安全库存、损耗、替代料、工序、排程、工资工时及财务对接不在本轮范围。

## 代码结构

物料档案新增分类筛选、列表和独立基本信息页（例如 `#materials/M001`），也可从库存记录的品名进入。支持本地编辑与保存；物料品号及参考单价保持不变。未展示的单价、选配属性、照片/描述和数据浏览页签保留空态。新补货、核算与状态属性目前只用于档案维护，不改变既有演示业务算法。

```text
src/demo/
  main.ts             # 无后端启动入口
  App.vue             # 布局、菜单和导航
  Inventory.vue       # 库存、仓库、出入库
  WarehouseDetails.vue # 仓库完整档案、编辑与本地保存
  Materials.vue        # 物料分类、列表和基本信息编辑
  material-profile.ts  # 物料字段、默认值和保存校验
  Procurement.vue     # 分析、请购、采购
  Drafts.vue          # 系统生成采购底稿的列表、快照明细与转采购
  Production.vue      # 生产计划
  DocumentEditor.vue  # 通用单据明细录入
  WorkOrders.vue      # 工单与多计划关联、人工进度
  Purchases.vue       # 采购审核、合并与来源追溯
  PurchaseEditor.vue  # 底稿/请购多选、手动物料和金额
  Receipts.vue        # 分批收货、关联入库单
  Issues.vue          # 领料单及仓库分配
  FinishedStock.vue   # 成品库存
  Shipments.vue       # 成品发货与物流记录
  model.ts            # mock 数据、单据模型和业务操作
  store.ts            # 响应式状态和本地原子提交
  model.test.ts       # 演示闭环及边界测试
  style.css           # 页面和响应式样式
vite.demo.config.ts   # 无代理的开发、静态构建配置
 tsconfig.demo.json   # 仅检查演示代码
```

原模板的 `src/main.ts`、布局、接口、插件及视图源码保留，当前演示不加载它们。默认开发、构建与预览命令已切换到演示入口，原 `.env` 的后端及权限配置对当前演示无效。

数据保存在浏览器同源 localStorage（`wsn-erp-demo-v1`），不发送到外部服务。清除浏览器数据或更换域名/端口会获得独立的初始数据。

采购底稿与请购单分开保存；一个生产计划一张底稿，包含多条物料，物料独立记录是否转采购；全部物料已转采购时底稿才标记已转采购。详情展示需求量、库存量、占用量、可分配量、已覆盖量及需购量快照，完整 BOM 仍在计划和需求分析中展示。历史缺失的库存计算快照显示为空；审核仅模拟前端状态，不实现完整权限体系。

## 首页与导航

默认进入首页工作台（`#home`），集中显示库存、生产、采购底稿与采购统计和业务流程入口。业务列表直接展示筛选、工具栏与表格，不重复放置顶部概览。左侧导航支持整体收起和分组独立收起，需求分析不设独立导航，由生产计划“分析缺料”打开弹窗；旧 `#analysis` 地址兼容转到生产计划。

## 工单工作台

首页优先展示工单总数、已完成、进行中及完成率，已完成按“已发货”统计。可用下拉搜索及上一/下一工单按钮切换进行中工单，查看关联计划、底稿、采购单、领料与发货记录数量，关联采购通过明细底稿追溯并排除合并旧单。

阶段进度为立项中 0%、采购中 25%、装配中 50%、待出货 75%、已发货 100%，仅表示业务阶段。当前工单完成后自动切换其他进行中工单；全部完成时保留最后工单的 100% 展示。首页同时保留库存、生产、采购概览，并新增收发货、领料及成品库存快捷入口。

## 页面缓存

同一应用内切换业务页面时使用 KeepAlive 保留筛选、分页、勾选、列表显示设置、表单与详情状态，并恢复各页文档滚动位置。库存/仓库/流水、请购/采购等共享组件按路由分别缓存，需求分析弹窗随生产计划缓存，档案详情按完整地址独立缓存。缓存仍读取响应式业务状态，单据变更后数据会同步更新。

缓存页面恢复时重新消费来源单据跳转指令；普通返回不重置原页面。弹窗和抽屉离页时隐藏、释放滚动锁，回来恢复原输入与详情。刷新页面会重新建立界面缓存；“重置数据”会清空业务数据与页面缓存。
